## 已实现的变化

- 使用 Windows App SDK 的发布排除机制，在生成单文件及哈希清单前移除 `DirectML.dll`、`onnxruntime.dll`、`onnxruntime_providers_shared.dll`。SDK 版本、trimming/AOT 配置保持原约束。
- 概览显示时每三秒探测；离开页面、隐藏、最小化时取消探测，恢复时立即刷新。TCP 端口所有者通过 [GetExtendedTcpTable](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-getextendedtcptable) 的 IPv4/IPv6 原生表读取，父进程通过 [Toolhelp 进程快照](https://learn.microsoft.com/en-us/windows/win32/api/tlhelp32/ns-tlhelp32-processentry32w) 查询；进程身份、PID 复用及归属检查保留。低频命令行身份核验仍可使用原有系统查询后备路径。
- 下载、安装、向导和软件更新通知合并为最多每 250 毫秒一批。每批共享下载展示快照；用户执行命令时读取实时状态。下载页每秒定时器仅更新尚在重试的倒计时，隐藏时停止展示刷新。
- 日志保留最多 2000 行、24 万字符，单条最多 2 万字符；先裁剪再拼接，200 毫秒批量展示。使用同一权威缓冲，消除独立待显示队列的重复和竞争；日志裁剪后按绝对字符位置恢复选择，完整磁盘日志保留。
- 普通 GUI 的单实例判断移到版本路由之后、应用资源提取之前；诊断及更新恢复保留既有约束。移除无引用 Entry 项目及 AsyncCommand，实际安装入口脚本与旧入口兼容仍保留。
- 内部缓存索引记录版本、关联 EXE 哈希、最后使用时间和完整文件基线。刚完成校验并原子发布的更新包复用其哈希登记，避免再次读取整包；公共登记与删除前检查仍独立校验。
- 窗口就绪三十秒后在空闲时安排维护，持久化限制实际维护每二十四小时最多一次。仅处理当前状态目录中已登记、至少七天未使用且无引用的工作台快照或受管更新包。当前、上一版、固定回退、待应用更新、未完成事务和运行进程相关目录受保护。
- 提取、更新、切换与维护通过共享/独占文件锁协调；删除前重新检查引用、内容哈希、路径范围、目录链接及进程身份。中断删除保留清单，下次只处理原清单未改变的剩余内容；重新启动被中断删除的快照时，仅补齐内嵌缺失文件并完整校验后复用。
- 未登记目录、模型、Python、环境备份、工具、下载断点和共享 .NET 解压缓存不自动清理。无法确认内容或进程身份时保留。

## 启动与资源测量

测试主机为 Windows 构建 `10.0.26200`（25H2），16 个逻辑处理器，PowerShell 7.6.5。脚本为 `launcher/scripts/Measure-LauncherPerformance.ps1`。冷启动指每次新配置和空 .NET 解压目录，不清空操作系统文件缓存；热启动为每个样本单独预热后直接启动已登记的同字节 EXE，排除旧入口再次路由的额外过程。就绪条件为窗口就绪日志、可见原生 HWND、输入空闲以及 WM_NULL 响应，不能等同于第一帧像素显示。

最终 r4 交替 A/B、B/A 运行每版 3 次冷启动、5 次热启动（16 份样本全部保留），汇总位于 `quiet-r4-performance/comparison.json`：

本地下载限速源的单连接耗时 32.82 秒，aria2 桥接 13.31 秒，四路并发约 2.47 倍；无限速源直接 aria2 为 3.39 秒、桥接为 9.28 秒。此为保留下载桥接的功能/开销测量，不是瘦身前后的下载提速。完整指标及说明见 `download-performance-fixtures/2c26905eb5054ec9a0092a0e6fd0c4be/download-performance/performance-report.json`。

## 缓存与构建清理

本次没有直接清理用户历史目录；新维护机制只对明确登记的目录生效。共享 .NET 解压缓存不在自动清理范围，其历史约 1.92 GiB 不计入收益。测试用临时模型/下载文件、r1/r2/r3 历史候选及预览状态按计划保留。

最后一次 87 项缓存/更新测试的独立 fixture 为 `output/cache-harness-results/07d885fa6b5b49b88d4aec46cccedd4a/launcher-cache-33124dfbe9194f24b22803649292d0f7/`。其中 13 份维护报告共记录释放 **190 字节**、删除 **7 个目录**、**24 条跳过**。这是测试小文件的实际量，不是用户空间释放；模拟崩溃前未写入报告的删除量未计入。该次测试输出保留于工具记录，fixture 与报告在磁盘上；没有将旧的 38 项日志冒称为这次 87 项的日志。

r4 构建、验证及验证进程退出后，`.publish-staging`、`.bundle-content`、本次 `.verification-*` 已全部移除；清单和体积报告已持久保存。失败现场未用递归通配符清理。安全清理脚本亦通过越界、junction 和报告保留测试。

## 验收边界

尚未拥有独立 Windows 10/不同 Windows 11 构建的测试环境，因此不能宣称完成全部受支持系统的兼容矩阵。候选保持原 SDK 和运行时依赖，不以本机成功代替跨版本验证。

展示快照频率与长日志压力由实际共用的核心限频/缓冲实现测试验证，尚无每五分钟前台、托盘、下载的完整 GUI A/B 采样，也未在真实千任务 GUI 中完整记录选择/滚动/编辑操作。现有原生 UI 冒烟、定向实现测试与下载引擎实传结果分别报告，不混作同一种证据。

候选未作为 GitHub Release 正式发布，为未签名构建。使用可直接打开候选 EXE；若要隔离试用，运行仓库 `launcher/scripts/Start-IsolatedCandidate.ps1 -CandidateDirectory <候选目录>`，其配置与解压缓存都在候选目录内。正常模式会使用既有状态；安装包会进入正常安装流程。
